# 목록 인테이크

프롬프트의 1/4이 4~7개짜리 목록이다. 그리고 v1.0.0 데이터에서 **배치 프롬프트 다음에
재지시가 올 확률이 단일 프롬프트 다음보다 1.27배 높았다.** 목록으로 주는 것 자체가
문제가 아니라, 목록을 한 덩어리로 받아 한 덩어리로 답하는 것이 문제다.

## 1. 쪼갠다

번호가 붙어 있으면 번호대로. 안 붙어 있으면 문장 단위로. 한 줄에 두세 개가 붙어 있는
경우가 많다 — "~수정해주고 그리고 ~도 추가해줘" — 그것도 쪼갠다.

쪼갠 목록을 **먼저 보여준다.** 이 단계에서 "그건 그런 뜻이 아니었는데"가 나오면,
잘못 만든 코드를 되돌리는 것보다 100배 싸다.

## 2. 갈림길만 되묻는다

각 항목을 셋으로 분류한다.

| 분류 | 처리 |
|---|---|
| **분명한 것** | 바로 한다. 묻지 않는다 |
| **두 갈래로 읽히는 것** | 묻는다 |
| **관례가 있는 것** | 정하고 가되, 무엇으로 정했는지 한 줄 적는다 |

되물을 때 지킬 것:

- **한 번에 묶어서 묻는다.** 항목마다 답을 기다리게 만들지 않는다. 새벽 작업 비중이
  40%다 — 왕복이 늘면 그날 작업이 끝나지 않는다.
- **선택지를 주고 묻는다.** "어떻게 할까요?"가 아니라 "A입니까 B입니까, 저는 A를
  추천합니다, 이유는 ○○"로 묻는다.
- **답을 몰라서 묻는 게 아니라, 갈려서 묻는 것만 묻는다.** 확인 절차처럼 되면
  사용자가 되묻기 자체를 싫어하게 된다.

무엇이 실제로 갈리는가 — 이 프로젝트에서 반복적으로 갈렸던 것들:

| 모호한 표현 | 갈리는 지점 |
|---|---|
| "이 화면", "여기" | 캘린더 하루치인지 오늘 할 일 탭인지 (두 화면이 비슷하다) |
| "할 일에 ~~하게" | 그 할 일 하나인지 카테고리 전체인지 |
| "캘린더에" | 지금 보는 캘린더 하나인지 전체 보기에도인지 |
| "~~도 추가해줘" | 이번 버전인지 백로그인지 |
| "~~로 바꿔줘" | 기존 동작을 대체하는지 옆에 추가하는지 (기존 사용자에게 보이는 변화) |
| "블록", "셀", "태그" | 캘린더 블록 / 목록 셀 / 칩 — 셋이 다르다 |

**추측해서 만들지 않는다.** 잘못 읽고 만든 것이 안 만든 것보다 비싸다. 되돌리는 데
시간이 들고, 그 사이 다른 것도 같이 바뀌어 있다.

## 2-1. 다음 프롬프트를 돕는다

되물어야 했다면, 답을 받은 뒤 **어떤 정보가 있었으면 안 물어도 됐는지** 한 줄 남긴다.

```
(참고) '이 화면'이 캘린더 하루치인지 오늘 할 일 탭인지 갈렸습니다.
       다음엔 탭 이름을 같이 주시면 바로 갑니다.
```

지킬 것:

- **한 줄.** 설명하지 않는다. 무엇을 덧붙이면 되는지만 말한다.
- **검토는 매번, 남기는 것은 판단.** 답을 받은 직후에 "남길 것이 있나"를 매번
  본다. 없으면 안 남긴다 — 매번 남기면 잔소리가 되고, 잔소리가 되면 되묻기 자체를
  싫어하게 된다. **두 번째로 같은 종류가 갈리면 그때는 반드시 남긴다.**
  (v1.3.0에서 다섯 번 되묻고 한 번도 안 남겼다. "반복될 때만"이라는 단서가
  판단을 요구했고, 판단하기 전에 잊혔다.)
- **탓하지 않는다.** "명확히 써주세요"가 아니라 "이걸 같이 주시면 한 번에 됩니다"다.
- 목적은 교정이 아니라 **다음 요청을 한 번에 끝내는 것**이다.

## 3. 백로그에 적는다

`docs/BACKLOG.md`에 **바로 하는 것까지 포함해 전부** 적는다. 지금 할 것만 머리에 담고
나머지를 채팅에 두면 나머지가 사라진다. 실제로 2026-08-01에 받은 14개 목록 중 절반은
그 뒤 다시 언급되지 않았다.

## 4. 순서를 정하고 이유를 한 줄 말한다

적은 순서는 대개 생각난 순서지 중요도 순이 아니다.

1. **깨져 있는 것** — 동작하지 않는 것이 예쁘지 않은 것보다 먼저다
2. **다른 것을 막고 있는 것** — 용어·구조를 정하는 일은 그걸 쓰는 화면들보다 먼저다
3. **같은 파일을 만지는 것끼리 묶는다** — 한 파일을 세 번 열지 않는다

## 5. 항목별로 돌려준다

**받은 항목 전부**에 상태를 붙인다. 하나도 빠뜨리지 않는다.

```
1. 태그 두 줄 흐르기      완료 — WrappingHStack 적용
2. 대체 공휴일 표시        완료
3. 알림 권한 시작 시 요청  안 함 — 첫 실행이 튜토리얼과 겹쳐 순서를 정해야 함. BACKLOG로
4. 리뷰 유도 동작           확인 필요 — 검증 카드 참조
```

`완료`는 R2까지 끝낸 것에만 쓴다. 사람 확인이 필요하면 `확인 필요`이고, 검증 카드를
같이 낸다 (`/handoff`).

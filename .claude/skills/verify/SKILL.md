# 회귀 훑기

**쓰는 때**: 심사 제출 전 / 버전 올리기 전 / 캘린더·튜토리얼·동기화 리팩터링 뒤.

## 누가 하나

| | 담당 |
|---|---|
| 빌드 (App · MoscoWidget) | AI |
| 테스트 실행 | AI |
| **아래 화면 항목 전부** | **사람** |

**AI는 시뮬레이터를 열지 않는다** (`CLAUDE.md` R2). 그러므로 이 목록은 AI가 채우는
체크리스트가 아니라 **사람에게 넘기는 목록**이다. AI가 하는 일은 빌드와 테스트를
돌리고, 이번 변경에서 실제로 위험한 절만 골라 `/handoff` 카드로 묶는 것이다.

전체를 다 넘기지 않는다. 일곱 절을 통째로 던지면 안 밟힌다 — **이번에 만진 코드가
닿는 절만** 고르고, 왜 그 절인지 한 줄 적는다.

앱 데이터를 지운 상태(첫 실행)에서 시작한다. 첫 실행 경로는 개발 중에 거의 안 밟히면서
가장 자주 깨진다.

여기 있는 항목 중 **로직으로 떨어지는 것은 테스트로 옮긴다** (R7). 옮긴 항목은 이
목록에서 지운다 — 사람이 매번 손으로 밟는 목록이 짧아지는 것이 이 문서의 목표다.
날짜 경계·반복 전개·시각 파싱·블록 배치가 1순위다.

```bash
xcodebuild -project Mosco/Mosco.xcodeproj -scheme App -sdk iphonesimulator \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' test
```

`test`가 빌드까지 한다. 실패하면 그 자리에서 고치고, 못 고치면 무엇이 왜 깨졌는지
카드에 적는다 (R1).

위젯을 만졌으면 `-scheme MoscoWidget`으로도 빌드한다. 앱만 빌드하고 넘어가서
익스텐션이 깨진 채 나간 적이 있다.

## 1. 첫 실행

- [ ] 사용법 안내가 뜨고, 건너뛰기가 된다
- [ ] 안내 버튼이 **글자 바깥을 눌러도** 눌린다
- [ ] 안내 중 입력창에 글자가 실제로 써진다 (오버레이 창이 키를 안 빼앗는지 — `TRAPS.md`)
- [ ] 안내가 입력창이나 지시 대상을 가리지 않는다

## 2. 캘린더

> **테스트로 옮겨간 것** (`MoscoTests`, 2026-08-18) — 사람이 밟지 않는다.
> 같은 날짜 중복 · 격자 연속성 · 블록이 0행부터 쌓임 · 빈 줄 없음 ·
> 여러 날 걸친 할 일 전개 · 하루 완료가 번지지 않음.
> **이 항목들이 의심되면 손으로 밟지 말고 `test`를 돌린다.**

- [ ] 날짜 칸을 꾹 누르면 **칸 전체**에 눌림 표시가 잡힌다
- [ ] 블록이 많은 날에 캘린더가 길어지고 스크롤된다
- [ ] 블록을 탭하면 그 날짜 하루치로 들어간다
- [ ] 공휴일·주말 색이 맞다

## 3. 할 일 만들기

- [ ] 하단 입력창이 보인다
- [ ] 키보드가 올라올 때 입력창이 튀지 않는다
- [ ] `7시 러닝` → 상단에 시각 확인이 뜨고, 확인하면 제목에서 시각 텍스트가 빠진다
- [ ] `4시~7시`에서 종료 시각까지 잡힌다
- [ ] 카테고리가 자동으로 붙고, 판별 중에는 태그 버튼이 안 눌린다
- [ ] 날짜·시각 없이도 만들어진다 (둘 다 옵셔널)
- [ ] 반복 일정: 종료 날짜 없이 만들어진다 (하루 완료가 번지지 않는 것은 테스트가 덮는다)

## 4. 목록과 셀

- [ ] 지난 미완료 → 오늘 순서로 보이고 `오늘로 가져오기`가 동작한다
- [ ] 편집 모드에서 바꾼 순서가 **다른 화면에서도** 유지된다
- [ ] 편집 모드에서는 검색이 잠긴다
- [ ] 탭 한 번에 완료된다
- [ ] 메모가 셀에 펼쳐 보이고, 눌러서 메모 화면으로 간다
- [ ] 메모를 길게 쓸 때 커서가 키보드에 안 가려진다
- [ ] 꾹 누르기 메뉴: 복사, 남은 시간 표시
- [ ] 카테고리 색이 **체크 동그라미 한 곳에만** 있다
- [ ] 태그가 여러 개일 때 두 줄로 흐른다
- [ ] 삭제 → 확인 → 지워지고, **다른 데이터가 날아가지 않는다**

## 5. 설정

- [ ] '캘린더'·'카테고리' 행을 누르면 각각의 화면으로 들어간다. 개수가 맞다
- [ ] 카테고리 추가·이름·색 변경
- [ ] 기본 카테고리는 삭제 불가, 이름·색은 변경 가능
- [ ] 카테고리 삭제 시 할 일들이 기본 카테고리로 넘어간다
- [ ] 셀 **전체**가 터치 영역이다
- [ ] 알림 전체 토글, 카테고리별 알림, 기본 10분 전
- [ ] 권한 없으면 토글이 안 켜지고 설정으로 보낸다
- [ ] **날씨 섹션에  Weather 상표와 법적 고지 링크가 있다** — 없으면 심사 반려된다

## 6. 실기기가 필요한 것 (시뮬레이터로도 판정 불가)

위 1~5절은 시뮬레이터로 되지만 어차피 사람이 밟는다. 이 절은 **시뮬레이터가 있어도
안 되는 것**이라 실기기를 따로 꺼내야 한다. 카드에 `[실기기 필요]`를 붙인다.

- [ ] 달 스와이프 체감 — 실기기에서만 드러난다
- [ ] 푸시 알림 실제 도착
- [ ] 날씨 표시 (위치 권한 허용 후, 하루치 상단 주간 스트립)
- [ ] 위젯 3종 + 잠금화면 위젯
- [ ] 라이브 액티비티 / 다이나믹 아일랜드 — 표기 규칙은 `TRAPS.md`
- [ ] iCloud 동기화 (기기 두 대 또는 앱 재설치)
- [ ] 애널리틱스 DebugView (`-FIRDebugEnabled` 필요)

## 7. 제출 전

- [ ] `project.pbxproj`의 버전 **네 곳** + 빌드 번호 네 곳
- [ ] `PRIVACY.md`의 수집 항목이 `Shared/Analytics.swift`의 이벤트와 맞는다
- [ ] App Review Notes에 날씨 기능 위치와 출처 표기 위치
- [ ] 릴리스 노트 — `RELEASING.md`의 규칙 넷
- [ ] `git tag -a V<버전>`
- [ ] 태그 뒤 `python3 tools/harness_report.py --version <버전> --append`

## 결과 쓰기

AI가 적는 것은 **자기가 실제로 돌린 것**뿐이다. 화면 항목에 결과를 적지 않는다.

```
빌드    App ✅ / MoscoWidget ✅
테스트  42개 통과, 0 실패
카드    1절 첫 실행 · 3절 할 일 만들기 — 튜토리얼 오버레이와 입력창을 만졌음
못 봄   위젯, 라이브 액티비티, iCloud — 실기기 필요
```

사람이 결과를 돌려주면 `docs/harness/verify-log.tsv`에 pass/fail 한 줄을 남긴다.
**애매하면 fail이다.** 이 파일이 R3 담당 지표(검증 통과율)의 원본이다.

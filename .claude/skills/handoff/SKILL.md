# 검증 카드 넘기기

## 왜 이 절차가 있나

이 프로젝트의 검증 사다리는 네 칸이고, 아래로 갈수록 비싸다.

| | 검증 | 성격 | 누가 |
|---|---|---|---|
| 1 | 빌드 | 컴파일만 본다 | AI |
| 2 | 테스트 (유닛 · UI) | 객관적 판정 | AI |
| 3 | 사람이 직접 만져보기 · 로그 붙여넣기 | 외부 판정 | 사람 |
| 4 | App Store 심사 | 외부 판정 | 외부 |

**실제 버그는 대부분 3번과 4번에서 나왔다.** 1.0 빌드 3은 WeatherKit 표기 누락으로
심사에서 반려됐다 — 가장 늦고 가장 비싼 자리에서 잡힌 것이다.

**2단에는 원래 "시뮬레이터에서 화면 열어보기"가 있었고, 2026-08-18에 없앴다.**
그 칸은 AI가 자기 결과를 자기가 채점하는 자리인데다 가장 비쌌다 — v1.0.0에서
1,015회, v1.1.0에서 716회의 도구 호출을 쓰고 산 것이 "그려졌다" 하나였다.
지금 그 자리는 테스트가 대신한다 (`CLAUDE.md` R2 · R7).

그래서 AI는 1·2번까지만 하고 **화면 판정은 전부 넘긴다.** 넘기는 방식이 중요하다.
"확인해줘"는 무엇을 확인할지 설계하는 일을 사람에게 떠넘기는 것이고, 그러면 확인이
대충 되거나 안 된다.

## 카드 형식

항목마다 네 줄이다. 이보다 길면 새벽에 안 읽힌다.

```
확인 요청

■ 태그가 두 줄로 흐르는지
  어디   캘린더 → 8월 20일 탭 → '치과 예약' 셀
  하기   카테고리를 3개 붙인 할 일을 하나 만든다
  통과   칩이 셀 폭을 넘지 않고 두 번째 줄로 내려간다. 셀 높이가 같이 늘어난다
  실패   칩이 잘리거나, 셀 밖으로 나가거나, 셀 높이가 그대로

■ 다이나믹 아일랜드 남은 시간 표기          [실기기 필요]
  어디   잠금화면 / 노치
  하기   30분 뒤 시각으로 할 일을 만들고 꾹 눌러 '남은 시간 표시'
  통과   '28분 전'처럼 나온다
  실패   '-2분'이나 '진행 중'이 나온다
```

- **[실기기 필요]** 를 붙일 것: 스크롤 체감·프레임, 푸시 알림 실도착, WeatherKit,
  위젯, 라이브 액티비티, 다이나믹 아일랜드, iCloud 동기화, 애널리틱스 DebugView.
- 앱 데이터를 지운 상태가 필요하면 그것도 `하기`에 적는다. 첫 실행 경로는 개발 중에
  거의 안 밟히면서 가장 자주 깨진다.
- **실패 조건을 반드시 적는다.** 통과 조건만 있으면 "애매한데"로 끝난다.

## 카드를 낼 때 같이 하는 것

- **빌드와 테스트 결과를 먼저 붙인다.** 이것이 AI가 확인했다고 말할 수 있는 전부다.
  스크린샷을 붙이지 않는다 — 시뮬레이터를 열지 않으므로 붙일 것이 없다 (R2).
- **테스트로 덮은 것과 카드로 넘기는 것을 나눠 적는다.** 카드가 길어지면 안 밟힌다.
  로직으로 떨어지는 항목이 카드에 남아 있으면 그건 테스트를 안 쓴 것이다 (R7).
- 못 본 것을 명시한다. "위젯은 확인 못 했습니다"가 "다 됐습니다"보다 낫다.
- 커밋 메시지 한 줄을 제안한다. 통과하면 바로 찍을 수 있게.

```
빌드    App ✅ / MoscoWidget ✅
테스트  MonthLayoutTests 7개 통과 — 월말/월초 중복, 5주·6주 격자
카드    아래 2건
못 봄   위젯 렌더링 (실기기)
```

## 스크린샷은 PR에서만

시뮬레이터 스크린샷을 찍는 자리는 **PR 본문 하나뿐이다.** UI를 만진 PR이면 대체로
넣는 게 맞고, 필요한지는 AI가 판단한다. 검증 카드에는 넣지 않는다 — 카드는 사람이
자기 눈으로 볼 것을 적는 문서이고, AI가 찍은 화면은 그 판단을 대신하지 못한다.

## 결과를 받으면

`docs/harness/verify-log.tsv`에 한 줄 append 한다. 이게 검증 통과율(R3의 담당 지표)의
원본 데이터다.

```
날짜	버전	영역	결과	무엇이 틀렸나
2026-08-20	1.2.0	셀 태그 줄	pass
2026-08-20	1.2.0	다이나믹 아일랜드	fail	31분 뒤 일정인데 표시 안 됨
```

- `결과`는 `pass` 또는 `fail`뿐이다. 애매하면 `fail`이다.
- 실패했으면 고친 뒤 **새 줄**을 추가한다. 기존 줄을 고치지 않는다 — 몇 번 왕복했는지가
  데이터다.
- 파일이 없으면 헤더부터 만든다.
